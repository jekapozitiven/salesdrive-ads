# Ads collector (SalesDrive → MyDrop → Firebase)

Считает рекламную статистику по кампаниям для вкладки «Реклама». Работает как `stats.py`:
фоновый скрипт на GitHub Actions собирает и пишет в Firebase, а вкладка только показывает.

## Этап 1 (сейчас) — разведка полей SalesDrive

Цель: увидеть, как реально называются в заказе **внешний номер**, **артикул**, **статус**.

### Установка (5 минут)

1. Создай **приватный** репозиторий на GitHub (напр. `salesdrive-ads`) и залей в него:
   ```
   collector.py
   .github/workflows/ads.yml
   README.md
   ```
2. Ключ SalesDrive (право **чтения заявок**):
   - Репозиторий → **Settings → Secrets and variables → Actions**
   - вкладка **Secrets** → **New repository secret**: имя `SALESDRIVE_API_KEY`, значение — твой ключ.
   - вкладка **Variables** → **New repository variable**: имя `SALESDRIVE_URL`, значение — твой домен, напр. `blackstreet.salesdrive.me` (без https).
3. (позже, для этапа 2) туда же: секрет `MYDROP_API_KEY` и переменная `FIREBASE_DB_URL` — как в `stats.py`.

### Запуск разведки

- Вкладка **Actions** → **Ads collector (SalesDrive)** → **Run workflow** (probe = `1`).
- Открой лог запуска: там будет **пример заказа** и **список полей**.
- Пришли мне этот вывод (или скрин лога) — по нему докрутим этап 2.

## Этап 2 (после сверки полей)

- артикул → категория (по API магазина, с кэшем);
- категория → кампания (маппинг правится во вкладке «Реклама», хранится в Firebase);
- джойн по внешнему № с MyDrop → дроп-цена, продажная, маржа, апрув;
- агрегаты по кампаниям/дням → `shop-reports/ads/<магазин>/<кампания>/<день>`;
- заказы со смешанными категориями → узел «потребує розподілу» (распределяешь вручную во вкладке);
- бюджет по кампаниям — расширим Google Ads скрипт (cost по campaign, раз в час).
